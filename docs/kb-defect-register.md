# 知识库第二轮缺陷排查（代码级）

> 方法：代码走查 + 临时 SQLite 可执行探针。
> 目的：找上一轮风险分析没覆盖到的**具体缺陷**，并给出修复与新增风险。

---

## 1. 探针结果

| 探针 | 结果 | 结论 |
|---|---|---|
| 编译九模块顺序 | `1,2,4,5,3,6,7,8,9` | 模块 3 被排到 4/5 之后 |
| 死亡角色省略 lifecycle | 第 1 章 dead → 第 2 章 active | 死亡状态被复活 |
| 认知关系更新 | 第 1 章 `[赵洵]` → 第 2 章只剩 `[马东]` | relations 被整体替换 |
| 新建 timer 当章结算 | `3 → 2` | 新倒计时被多减一章 |
| 第 10 章 timer 编译第 2 章 | 可见 | 未来倒计时泄漏 |
| 账本 1000 铜钱 + 2 灵石，花 500 灵石 | `passed=True` | 不同币种被相加 |
| “花了一千铜钱” | 无违规 | 中文数字未识别 |
| “花去500铜钱” | 无违规 | 动词未覆盖 |
| 无 meta 时连续取章节号 | `1, 1` | 存量章节会塌成 1 |
| 同名作品 | 允许创建 | 标题定位有歧义 |
| `kb_source_meta` | 无 `(work, chapter)` 唯一约束 | 可重复章节号 |

## 2. 缺陷登记

## 3. 问题链：修复会带出什么

| 修复 | 直接收益 | 带出的新问题 | 二次方案 |
|---|---|---|---|
| 继承 lifecycle | 死亡不复活 | 抽取器“没提到”≠“活着” | 显式 `lifecycle_mentioned` 字段 |
| 合并 relations | 关系不丢 | 关系删除无法表达 | `relation_status=removed` |
| timer 按创建章 | 不早减 | 旧 timer 无创建章 | 回填为首次出现章 |
| 按币种校验 | 不串账 | 币种别名（铜钱/铜板） | 币种字典 |
| 章节号回填 | 存量可用 | 标题不规范 | 人工覆盖表 |
| 长章分块 | 不截断 | 跨块场景合并 | 场景序号全局化 |
| 拆书独立流程 | 省成本 | 两套任务 | 统一 job 抽象 |
| OpenAPI 生成 | 文档不漂 | 生成器复杂 | 先手写补全 |
| 唯一约束 | 不重名 | 旧数据冲突 | 迁移前去重 |

## 5. 建议新增的回归测试

1. 编译顺序：模块标题必须 `1..9` 递增
2. 死亡角色：省略 lifecycle 时保持 dead
3. 关系合并：旧关系保留，新关系追加
4. timer：创建章不减，下一章减
5. 编译 as-of：未来 timer 不出现
6. 多币种：灵石不足必须报错
7. 中文数字：一千/五百能识别
8. 章节号：无 meta 时按标题/顺序回填
9. 唯一约束：重复章节号被拒绝
10. OpenAPI：path 集合与路由一致

---

## 6. 结论

这一轮找到的都不是“模型不行”，而是**省略语义、单位、顺序、约束**四类代码缺陷：

- 省略字段被当成默认值（lifecycle、timer）
- 多单位被当成同一种（币种）
- 插入顺序被写死（模块 3/4/5）
- 缺少唯一约束和归属校验（章节号、别名、作品名）

它们可以在不改架构的前提下修完；建议先修 P0 的 9 项，再进入章节记忆的实现。
