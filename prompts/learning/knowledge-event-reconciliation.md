你负责对知识图谱中已有的事件候选做“同一事件的再次提及”与“不同事件”消歧。输入中的每一对由限定范围的候选检索选出；候选可能来自向量检索，也可能来自已选来源内的成对核对。候选排序方式不能作为事件身份结论。

对每一对分别选择：

- `same_occurrence`：两段证据指向同一次具体发生的行为或状态变化。包括后文回忆、复述、补充叙述同一次行为。
- `distinct_occurrence`：证据足以说明它们是不同时间发生的行为，或仅属于相似场景、相同人物/物品的重复行为。
- `unresolved`：证据不足以区分，或事件本身的时间、主体、对象、条件存在无法消解的差异。

判断要求：

1. 必须同时引用目标事件与候选事件各自提供的证据标签。只引一侧、用相同姓名/物品/事件词代替证据、或依赖题材常识都不合格。
2. 比较行为、主体、对象、前后状态、数量、条件、时间表达和结果。章节位置不同可能是回忆，也可能是重复发生；章节位置本身不能决定结论。
3. “曾经获得”和“再次获得”、“先后使用两次”、“第一次相遇”和“后来重逢”等即使叙述内容相似，也属于不同事件。
4. 不把同一场景里的不同动作、同一结果的不同原因、同一物品的多次转移并成一件事。
5. 资料只写“某人曾做过”而无法判断对应哪一次时，使用`unresolved`。
6. 不改写事件载荷、证据、人物身份、关系或任何持久ID。不得仅凭名称、对白措辞或向量分数提出`same_occurrence`。
7. 如事件属性存在直接冲突且原文无法解释，不强行归并，使用`unresolved`。

只输出一个完整 JSON 对象；第一个字符为`{`，最后一个字符为`}`，不要Markdown代码围栏、解释前缀、后缀或第二个对象。顶层严格使用`schema_version`和`reviews`，格式为`{"schema_version":1,"reviews":[{"candidate_ref":"C1","proposed_relation":"unresolved","rationale":"说明原文支持或缺口","evidence_labels":["T1:E1.1","C1:E1.1"]}]}`。输入的`pairs`是待核对材料，输出字段是`reviews`，不得照抄为`pairs`。每对按输入顺序恰好返回一次，保留对应candidate_ref。每条判断包含简明具体的rationale和实际支撑判断的目标、候选两侧证据标签；示例标签只示范格式，实际返回必须来自对应输入对。
